# ✈️ TestFlight - Быстрый гайд по бета-тестированию iOS приложения

## 🎯 Что такое TestFlight?

**TestFlight** — официальная платформа Apple для бета-тестирования iOS, iPadOS, watchOS и tvOS приложений. Позволяет тестировать приложение на реальных устройствах перед публикацией в App Store.

### Преимущества:
- ✅ До 10,000 внешних тестеров
- ✅ Автоматический сбор крашей и метрик
- ✅ Feedback от тестеров прямо в app
- ✅ Быстрая проверка (только автоматический скан для Internal Testing)
- ✅ Обновления без App Store Review (до 90 дней)
- ✅ Тестирование на разных версиях iOS

---

## 🚀 Быстрый старт (5 шагов)

### 1. Соберите iOS билд через EAS
```powershell
cd app-bootstrap
eas build --platform ios --profile production
```

⏱️ Время: 15-20 минут

### 2. Дождитесь обработки Apple
Билд автоматически появится в TestFlight через **10-30 минут** после завершения сборки EAS.

Проверьте статус: https://appstoreconnect.apple.com → TestFlight

### 3. Добавьте Internal Testers
1. App Store Connect → TestFlight → Internal Testing
2. Нажмите **"+"** рядом с "Testers"
3. Введите email адрес тестера (должен быть в Apple Developer Team)
4. Тестер получит email-приглашение

### 4. Тестеры устанавливают приложение
1. Установить **TestFlight** app из App Store: https://apps.apple.com/app/testflight/id899247664
2. Открыть email-приглашение и нажать **"View in TestFlight"**
3. Принять приглашение
4. Нажать **"Install"** в TestFlight app

### 5. Собирайте feedback
Тестеры могут:
- Отправлять скриншоты проблем прямо из app (потрясти устройство)
- Писать текстовый feedback
- Все крэши автоматически собираются

## 📊 Типы тестирования

### Internal Testing (до 100 тестеров)
```
✅ Мгновенный доступ (без Apple Review)
✅ Только для команды (Apple Developer Team members)
✅ Идеально для первичного тестирования
✅ Можно добавить/удалить тестеров в любой момент
```

**Когда использовать:**
- Первичная проверка билда
- Тестирование новых фич
- QA перед External Testing

### External Testing (до 10,000 тестеров)
```
⏱️ Требует Apple Review (1-2 дня, только первый раз)
✅ Можно пригласить кого угодно по email
✅ Публичная ссылка для приглашения
✅ Группы тестеров (например, "VIP Users", "Beta Testers")
```

**Когда использовать:**
- Широкое бета-тестирование
- Сбор feedback от реальных пользователей
- Нагрузочное тестирование
- Финальная проверка перед App Store

## 📝 Пошаговая инструкция

### Шаг 1: Настройка App Store Connect

#### Создание Internal Testing группы
```
1. App Store Connect → TestFlight → Internal Testing
2. Группа "App Store Connect Users" создана автоматически
3. Добавьте тестеров из вашей команды:
   - Users and Access → Users → + (пригласить)
   - Назначьте роль "Developer" или "App Manager"
   - Они автоматически появятся в Internal Testing
```

#### Создание External Testing группы
```
1. TestFlight → External Testing → "+" (Create Group)
2. Название группы: например "Beta Testers"
3. Enable automatic distribution (опционально):
   ✅ Новые билды автоматически идут тестерам
   ❌ Вы вручную выбираете какой билд отправить
```

### Шаг 2: Test Information (обязательно для External)

```
Beta App Description:
"В этой версии добавлены:
- AI-анализ стартапов
- Карта событий
- Исправлены ошибки с авторизацией

Ждем ваших отзывов!"

Feedback Email: beta@startuphub.kz
Privacy Policy URL: https://github.com/.../PRIVACY_POLICY.md
```

**Отправить на проверку** → ждать 1-2 дня (только первый раз)

### Шаг 3: Приглашение тестеров

#### Способ 1: По email (персонализированно)
```
External Testing → выберите группу → Testers → "+"
Введите emails → Send Invites

Плюсы:
✅ Контроль кто получает доступ
✅ Персональные приглашения

Минусы:
❌ Надо вручную добавлять каждого
```

#### Способ 2: Публичная ссылка (быстро)
```
External Testing → группа → Enable Public Link

Получите ссылку вида:
https://testflight.apple.com/join/XXXXXXXX

Поделитесь ссылкой:
📱 Социальные сети
💬 Telegram/WhatsApp группы
📧 Email рассылка
🌐 На сайте

Плюсы:
✅ Не нужно знать emails
✅ Быстрое распространение

Минусы:
❌ Любой с ссылкой может присоединиться (до 10,000)
```

### Шаг 4: Мониторинг тестирования

```
TestFlight Dashboard показывает:

📊 Metrics:
├── Installs: количество установок
├── Sessions: количество запусков
├── Crashes: краши с stack trace
└── Feedback: отзывы тестеров

📈 Details по билду:
├── Install Rate: % тех кто установил из приглашенных
├── Active Testers: активные в последние 7 дней
├── Crash-Free Sessions: % сессий без крашей (целевой: >99%)
└── Feedback Count: количество отзывов
```

## 💡 Best Practices

### 1. Начните с небольшой группы
```
✅ 5-10 внутренних тестеров сначала
✅ После стабилизации → 50-100 внешних
✅ Постепенно увеличивайте до 500-1000

❌ НЕ приглашайте сразу 10,000 тестеров
   Баги будут видеть все, плохая первая impression
```

### 2. Четкие инструкции для тестеров
```
Создайте документ с:
📝 Что тестировать (список фич)
🐛 Как сообщать о багах
📧 Куда отправлять feedback
⭐ Что особенно важно проверить в этой версии
```

Пример: создайте Notion/Google Doc и дайте ссылку в Beta App Description.

### 3. Регулярные обновления
```
✅ Новый билд каждые 3-7 дней
✅ Changelog в Beta App Description
✅ Реагируйте на feedback быстро

Тестеры видят что вы активны → больше вовлеченности
```

### 4. Используйте группы тестеров
```
Создайте несколько групп:
├── "Core Team" (5-10 человек) → все билды
├── "Early Adopters" (50 человек) → стабильные билды
└── "General Beta" (500+ человек) → финальные билды перед релизом
```

### 5. Мониторьте метрики
```
Критичные показатели:
✅ Crash-Free Rate > 99%
✅ Feedback Response Time < 24 часа
✅ Active Testers > 30% от приглашенных

Если метрики плохие:
- Спросите тестеров почему не используют
- Улучшите onboarding
- Добавьте стимулы (ранний доступ к фичам)
```

## 🐛 Сбор и обработка Feedback

### Как тестеры отправляют feedback:

#### Способ 1: Встроенный в TestFlight
```
1. Потрясти устройство в приложении
2. Появится окно "Send Beta Feedback"
3. Можно добавить скриншот и описание
4. Автоматически включает device info и logs
```

#### Способ 2: Через TestFlight app
```
1. Открыть TestFlight
2. Выбрать ваше приложение
3. Нажать "Send Feedback"
4. Написать текст и отправить
```

### Где смотреть feedback:

```
App Store Connect → TestFlight → Feedback

Фильтры:
├── By Build: конкретный билд
├── By Tester: конкретный тестер
├── By Device: тип устройства
└── By Date: временной период

Каждый feedback содержит:
- Текст от тестера
- Скриншоты (если есть)
- Device info (модель, iOS версия)
- Build version
- Email тестера (можно ответить)
```

## ⚙️ Настройки и лимиты

### Лимиты TestFlight:

| Параметр | Лимит |
|----------|-------|
| Internal Testers | 100 |
| External Testers | 10,000 |
| Билды на версию приложения | 100 |
| Срок жизни билда | 90 дней |
| Одновременных External групп | 100 |
| Размер билда | до 2GB |

### Как продлить тестирование > 90 дней:

```
Вариант 1: Увеличить buildNumber
- Измените buildNumber в app.json: "1" → "2"
- Соберите новый билд
- Билд будет доступен еще 90 дней

Вариант 2: Увеличить version
- Измените version: "1.0.0" → "1.0.1"
- Новая версия = новый счетчик 90 дней
```

### Автоматическое увеличение buildNumber:

В `eas.json`:
```json
{
  "build": {
    "production": {
      "ios": {
        "autoIncrement": true
      }
    }
  }
}
```

Теперь каждая сборка автоматически увеличивает buildNumber!

## 🚨 Типичные проблемы и решения

### "Build is processing" более часа
```
Причины:
- Apple обрабатывает билд (обычно 10-30 минут)
- Ошибка при обработке

Решение:
1. Проверьте email на уведомления от Apple
2. Если есть ошибка → пересоберите с исправлениями
3. Если нет ошибки → просто подождите (до 2 часов)
```

### "Missing Compliance Information"
```
Появляется после обработки билда.

Решение:
1. TestFlight → выберите билд
2. "Provide Export Compliance Information"
3. Вопрос: "Does your app use encryption?"
   - Выберите "No" если не используете дополнительное шифрование
   - HTTPS не считается дополнительным шифрованием
4. Submit
```

### "Expired Build" / "Beta App Unavailable"
```
Билд живет 90 дней, потом истекает.

Решение:
1. Увеличьте buildNumber в app.json
2. Соберите новый билд: eas build --platform ios
3. Новый билд появится в TestFlight
```

### "Cannot Accept Invite"
```
Причины:
- Тестер использует другой Apple ID
- Приглашение истекло (30 дней для External)
- TestFlight app устаревший

Решение:
1. Попросить тестера проверить Apple ID
2. Обновить TestFlight app до последней версии
3. Отправить новое приглашение
```

### "Too many testers"
```
Лимит External Testers: 10,000

Решение:
- Удалите неактивных тестеров
- Создайте новую External группу для новых тестеров
- Рассмотрите переход на Production (App Store)
```

## 📈 Метрики успешного бета-теста

### Целевые показатели:

```
✅ Crash-Free Rate: > 99%
   (99% сессий без крэшей)

✅ Install Rate: > 50%
   (50% приглашенных установили app)

✅ Active Testers: > 30%
   (30% установивших активны)

✅ Feedback Response: < 24 часа
   (отвечаете на feedback быстро)

✅ Critical Bugs: 0
   (нет блокирующих багов)

✅ Average Rating: > 4.0 / 5.0
   (если собираете рейтинги)
```

### Красные флаги:

```
🚨 Crash-Free Rate < 95%
   → Не публикуйте в App Store, много крашей

🚨 Active Testers < 10%
   → App неинтересен или плохой onboarding

🚨 Много негативного feedback
   → Переработайте UX перед релизом

🚨 Критические баги не исправлены
   → Продлите бета-тестирование
```

## ✅ Чеклист перед финальным релизом

Перед отправкой в App Store убедитесь:

- [ ] TestFlight бета-тестирование > 2 недель
- [ ] Минимум 50 активных тестеров
- [ ] Crash-Free Rate > 99%
- [ ] Все критические баги исправлены
- [ ] Positive feedback от большинства тестеров
- [ ] Приложение работает на разных версиях iOS (14+)
- [ ] Протестировано на разных устройствах (iPhone, iPad)
- [ ] Onboarding понятен новым пользователям
- [ ] Performance оптимизирован (быстрый запуск)
- [ ] Контент проверен (нет placeholder текстов)

## 🎉 Готово к App Store!

После успешного TestFlight:

1. **Выберите стабильный билд**

2. **Заполните метаданные**
   - См. полное руководство в `DEPLOYMENT.md`

3. **Submit for Review**
   - Обычно 24-72 часа на проверку

4. **После одобрения**
   - Можете выпустить сразу или по расписанию
